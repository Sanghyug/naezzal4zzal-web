# 출시 기능 운영·복구·되돌리기

## 화면과 실행

검토용 로컬 주소: `http://127.0.0.1:5173/` (`npm run dev:launch`).
체험 계정 이름은 영문/숫자이며 같은 이름은 같은 모의 계정이다.
모의 로그인·충전·영상은 실제 결제·OpenAI·HeyGen을 호출하지 않는다.
기본 사진 AI 분석도 이 모드에서는 차단하고 직접 맞추기로 계속한다.
검사에는 사람이 없는 색상 네 컷과 합성 영상을 사용했다.

`http://127.0.0.1:5173/?operator=1`에서 `operator` 모의 계정으로 로그인하면
운영 관리 화면을 검토할 수 있다. 이 우회는 로컬 전용이고 Vercel에는 없다.
실제 운영 관리 화면도 같은 경로지만 서버 `LAUNCH_ADMIN_IDS`에 있는 Supabase UID만 허용한다.
운영자 계정도 일반 인증을 거치며 URL 파라미터는 권한을 부여하지 않는다.

공통 프런트는 유지했다. 기존 `npm run build`는 출시 화면을 기본 비활성화하고,
`npm run build:launch`가 출시 화면을 켠다. 기존 iOS/Android/Toss 빌드 명령은 보존했다. 출시 서버를 켜면 예전 사무실 코드로 새 영상을 만드는 POST는 차단하고, 기존 서명 완성본 확인·다운로드는 유효기간 동안 유지한다.
본 범위는 웹 출시이며 스토어 OAuth/IAP를 구현했다고 주장하지 않는다.

| 탈퇴 식별 해시 | 중복 선물 방지용 HMAC, 90일 후 제거 |

이 값은 DB 설정이며 화면과 서버가 같이 읽는다. 선물 가능 여부는 로그인 시작 때 재조회하고
열린 화면도 30초·포커스 복귀 시 갱신한다. 동시 마지막 가입은 서버 트랜잭션에서 한 명만 지급한다.
보상 설정을 중지하면 지급은 즉시 중지된다. 이미 유효한 보상 대기는 재확인 때 조건·월 한도 안에서 처리한다.

비용 한도는 공식 요금에 근거한 **보수적 예약**이지 공급자 청구서에 대한 절대 상한은 아니다.
가격/모델을 바꾸면 예약값도 다시 확인한다. 실패한 시도의 비용 예약은 보수적으로 일일 예산에 남긴다.
월 누적 무료 지급 비용도 관찰하고 계정·선착순·초대 한도를 과도하게 올리지 않는다.

## 장부와 저장 구조

- 기준은 서버 DB. 무료·유료 지급 lot, 남은 수량, 예약 수량, 취소 잠금, 원인 주문·작업·초대를 구분한다.
- 무료 우선 예약 → 외부 생성 → 무음 결과 저장 → 사용 확정. 확정 실패만 원래 lot에 예약 해제한다.
- 결제 주문과 영상 작업은 다른 기록이다. 구매별 사용량을 남겨 미사용 전액 취소와 부분 사용 문의를 구별한다.
- PG의 서버 조회/승인 결과만 신뢰한다. 웹훅 본문 상태·클라이언트 금액은 지급 근거가 아니다.
- PostgreSQL은 환경별 상태 행에 `SELECT ... FOR UPDATE`를 잡고 장부 이벤트를 별도 audit 테이블에도 추가한다.
  무료 슬롯·초대자/친구·취소/사용 경쟁까지 한 번에 직렬화한다. 외부 API는 DB 잠금 밖에서 호출한다.
- 초기 100계정 검토 규모를 위한 단순한 설계다. 큰 트래픽 전에는 사용자/주문별 테이블로 분리하고
  전용 작업 큐·관리 통계를 추가해야 한다. 실제 PostgreSQL 연결·RLS는 아직 외부 계정 연결 후 검증해야 한다.
- 로컬 검토는 SQLite `BEGIN IMMEDIATE`+WAL로 같은 도메인 로직을 사용한다.
  로컬 DB는 `artifacts/launch/demo.sqlite`, 파일은 `artifacts/launch/storage/`이며 Git·배포에 제외된다.
- 실제 저장소는 Supabase 비공개 버킷이다. 결과 URL을 공개하지 않고 서버가 계정 소유권을 확인한 뒤 파일을 전달한다.

## 중단과 복구

장애 때 `?operator=1`의 운영 관리에서 사유를 적고 다음을 각각 중지한다.

- **새 결제 중지:** `payments=false`. 이미 승인 중인 주문 조회/취소·복구는 계속 가능하다.
- **무료 지급 중지:** `gifts=false`, `invites=false`. 기존 잔액을 삭제하지 않는다.
- **AI 생성 중지:** `generation=false`. 신규 제작·유료 사진 분석을 중지하고 기존 작업 확인은 계속한다.

PG 통신이 불명확하면 고객에게 재결제를 권하지 않는다. 구매 내역의 상태 다시 확인은
저장 주문·paymentKey로 PG를 조회해 승인 뒤 DB 오류를 복구한다. 취소 중에는 해당 구매 lot을 잠근다.
응답이 유실돼도 PG가 CANCELED인지 재조회해 장부 취소를 한 번만 반영한다.

영상 통신이 끊겨도 작업 ID·멱등성 키·단계를 보존한다. 작업별 240초 lease로 동시 실행을 막는다.
HeyGen 접수 결과가 불명확할 때는 같은 키만 사용하고 23시간이 지나면 새 제출을 멈춰 운영자 확인으로 둔다.
GPT 분석도 계정·입력 해시·분석 버전으로 잠가 동시에 한 번만 호출한다. 응답이 불명확하면 자동 재분석하지 않는다.
공급자의 확정 failed/cancelled만 자동 복구한다. 다운로드·DB·후처리 지연은 예약을 유지하고 같은 작업을 재확인한다.
운영자가 기술 실패를 확인한 작업은 서버 관리 API `releaseConfirmedFailure`에 작업 ID와 구체적인 사유를 남겨 해제할 수 있다.

`GET /api/launch?action=maintenance`는 `Authorization: Bearer <CRON_SECRET>`으로 인증한다.
진행 중 작업을 최대 한 건씩 이어가고, 승인/취소 대기 주문을 재조회하며 만료 파일·입력·캐시를 삭제한다.
앱의 제작 내역을 열어도 같은 작업을 이어간다. `vercel.launch.json`에 2분 주기 설정을 준비했다.
Hobby에서는 잦은 cron 배포가 거절되므로 **요금제와 DB를 연결하기 전 이 운영 설정으로 배포하지 않는다**.
현재 일반 `vercel.json` 미리보기에는 주기 실행을 등록하지 않았다.
주기 작업이 미설정이면 자동 보관 삭제 시각을 보장할 수 없으므로 공개 출시 조건으로 반드시 활성화한다.

롤백은 코드·화면 플래그만 되돌린다. 이미 지급·예약·사용·취소한 DB·audit 장부를 지우거나 예전 스냅샷으로 덮어쓰지 않는다.
스키마가 호환되는 동안 기존 운영 경로로 되돌리고 남은 주문/제작은 새 관리 API에서 마무리한다.
운영 전 DB 백업과 복구 절차를 확인한다. 기존 운영 배포와 ChantKPop은 이번 작업에서 변경하지 않았다.

## 남아 있는 한계와 공개 조건

- 소셜 로그인은 한 실제 사람의 여러 계정을 완벽히 막지 못한다.
- GIF 확인은 실제 GIF 바이트, 4~80 프레임, 크기·움직임, 일회성 번호, 방문/계정, 중복 해시를 검사하고 파일은 버린다.
  브라우저가 이 앱에서 새로 만든 개인 사진 GIF인지 완벽하게 증명하지는 못한다. 합성/수정 GIF를 만드는 남용은 가능하다.
  가입 선착순·초대 월 한도·요청 제한·전체 지급 중지·일일 예산을 함께 사용한다. 같은 와이파이라는 이유로 보상을 거절하지 않는다.
- GIF가 너무 크거나 검증 실패여도 무료 저장은 막지 않는다. 초대 보상만 보류하고 안내한다.
- 카카오톡 내장 브라우저에서 Google 로그인이 제한될 수 있다. 이 브라우저 편집을 저장하고 외부 브라우저 안내를 제공한다.
  다른 브라우저로 IndexedDB 사진을 자동 이전하지 않으므로 필요 시 사진을 다시 불러와야 한다고 명시한다.
- 실제 iPhone Safari·Android Chrome·카카오톡 앱, 실제 OAuth·토스 테스트/실결제·도메인 DNS는 미확인이다.
- 개인정보 해외 처리, 거래기록 보관, 부분 환불, 사업자 표시와 비공개 문의 연락처는 최종 정책 확인 전이다.
- 운영용 유료 계약·키·도메인·고객 실결제 승인 없이 공개 결제 출시를 완료했다고 표현하지 않는다.
